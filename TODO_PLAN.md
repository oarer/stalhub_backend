## 1. Патч-ноуты
**Решение:** новая Prisma-модель `PatchNote` (id, slug, title, excerpt, content MDX, image_url, tags, is_published, published_at, author_id, views) + CRUD в `/api/v1/admin/patch-notes` (permission `articles:manage` переиспользовать или новый `patchnotes:manage`).
Фронт: `/patch-notes`, `/patch-notes/[slug]`, админка `/admin/patch-notes` (таблица + модалка create/edit как `AdminArtForm`), виджет на лендинге.
Альтернатива (если хочешь без миграции): переиспользовать `Article type=STALHUB`. Вопрос к юзеру.

## 2. Stalcraft-форматирование + градиенты
**Что известно:** `stalcrafttext` — пример форматирования (цветные коды, градиенты). В проекте такого нет, статьи — MDX.
**Решение:** новый тул `src/views/calcs/text/` + роут `/calcs/text` (или `/tools/text-formatter`):
- парсер кодов STALCRAFT (`<#hex>`, градиент `<g:#a:#b>text</g>` — точный синтаксис уточнить по примеру stalcrafttext),
- live-превью (игровой стиль), копирование результата, пресеты градиентов,
- переиспользуемый компонент `<StalcraftText/>` для патч-ноутов/статей.
Нужен пример синтаксиса от юзера / ссылка на stalcrafttext.

## 3. Арсенал: иконки + «Магазин»
**Сейчас:** `ArsenalView` — таблица без иконок, ввод репутации вручную. Бэк `GET /arsenal` отдаёт `arsenal.json` + цены.
**Решение:**
- бэк: добавить `icon`/`category` в ответ (резолв через `listing.json` по `id`), либо фронт резолвит `https://cdn.stalhub.dev/db/icons/{category}/{id}.png` как в `ItemsList`.
- фронт: колонка с иконкой (как `BuildCard`), новая вкладка `Калькулятор | Магазин` (`Tabs`).
- «Магазин»: 3 группы 10k / 20k / 30k ◉. Быстрый выбор нужного кол-ва репутации (клик → подставляет в калькулятор / фильтрует). Ассортимент — захардкодить конфиг `src/constants/arsenal-shop.const.ts` с `id` из БД (поиск по `listing.json`).
- ID искать: `curl https://cdn.stalhub.dev/db/listing.json | jq` по названиям («Руна», «АК-12», «Fortis SHIFT», «Перо» и т.д.). `(А)` = арсенальная версия — уточнить суффикс id.
- Правая колонка со стрелками `➤` — трактую как «обмен: отдать → получить» (напр. `Fortis SHIFT Vertical ➤ Рукоятка «Перо»`). Уточнить.

## 4. Творчество: фильтры
**Неясность:** что такое «Творчество» — `articles`, `arts` или `builds`? По сортировкам `BUILD_SORTS` похоже на сборки/статьи.
**Решение (предварительно):** добавить `sort=newest|oldest|views|stars` в `ArticlesView` (и/или `BuildsPublicView`), пробросить в query `articleQueries.publicList` + бэк `GET /articles/public?sort=`. Звёзды — считать через `Star` (`target_type ARTICLE/BUILD`).
Нужна подсказка юзера: какой раздел.

## 5. Арты: вкладки обычные/nsfw/все + age-gate
**Сейчас:** `ArtsView` — фильтр `ALL/NSFW`, блюр + `useNsfwGateStore` + `Modal` 18+.
**Решение:** три таба `Все | Обычные | NSFW` (`Tabs`), при первом переходе в `NSFW` — модалка возраста (подтверждение → `localStorage nsfw-confirmed`, блюр снимается). Обычные = `type=DEFAULT`, NSFW = `type=NSFW`. Бэк уже отдаёт `type`, менять не надо, только фронт + стор.

## 6. Сборки: открытие по клику
**Сейчас:** `BuildsPublicView` — сетка `BuildCard`, открытия детальной, видимо, нет (редактор в `views/calcs/builds`).
**Решение:** клик по карточке → модалка `BuildDetailModal` (как `HoverBuildCard` расширенная) или роут `/builds/[id]` с полным составом, ценой, кнопкой «Открыть в конструкторе». Переиспользовать `BuildCard` + `buildApiQueries.get(id)`.

## 7. Серверы: выбросы + пиковый онлайн
**Сейчас:** `ServerStatusView` — `latest()` + `history(hours)` (табы 6H/24H/7D), данные из `serverOnlineSnapshot` (крон).
**Решение:**
- история пиков: новый бэк `GET /server-online/peaks?days=30` — агрегация `MAX(online)` по дням (`groupBy date_trunc`), фронт — таб `День | Месяц` + таблица/график пиков (`OnlineChart` расширить).
- выбросы (эмиссии): источника в бэке нет. Варианты: (а) парсить STALCRAFT API/лаунчер, (б) ручной ввод через админку + таблица будущих/прошлых выбросов. Нужен источник от юзера.
- Хранение выбросов: новая модель `Emission(server_id, starts_at, ends_at?)` если автомат невозможен.

## 8. Игроки: сводка статистики
**Сейчас:** `PlayerView = HeroView + ClanView + ClanHistory + StatsView + OperationsSection`.
**Решение:** новый блок `PlayerSummary` сверху:
- КД общий (kills/deaths из `player.stats`), КД сессий (агрегация `operations/sessions`), split PvE/PvP (по `participants`/`operations` типам — уточнить поля API),
- больше PvE/PvP: сессии, винрейт, средний урон (если есть в `operations.cache`).
Нужен пример ответа `GET /player/:region/:character` + `operations/sessions`, чтобы знать поля.

## 9. Бартер-калькулятор с деревом
**Сейчас:** только просмотр `Barter.tsx` (1 уровень: `recipes` + `used_in`), бэк `GET /barter/:item_id`.
**Решение:** новый роут `/calcs/barter` + `BarterCalcView`:
- селект предмета (`ItemSearch` по `listing.json`, фильтр «только крафтящиеся» — те, что есть в `barter_recipes.json`),
- дерево: рекурсивный `GET /barter/:id` до глубины N (кэш), отрисовка дерева (как `HideoutView` граф или вложенный список),
- чекбокс «этап пройден» на каждом узле (состояние в `localStorage` + пересчёт суммарных остатков),
- суммарная таблица необходимых базовых ресурсов с ценами (аукцион).
Бэк менять не надо (или добавить `GET /barter` список доступных).

## 10. Донат-калькулятор
**Сейчас:** ничего, есть `donate-calculator.json` в корне бэка (14 дней окно, `stalcoins`, `market.price/median`).
**Решение:** роут `/calcs/donate` + `DonateCalcView`:
- ввод stalcoins → таблица `цена рынка / stalcoins = руб/монета`, сортировка по выгодности (`price_per_coin DESC`), фильтр `has_market=true`, учёт `amount` (паки x10/x25),
- данные: либо статичный импорт json, либо новый бэк `GET /donate-calculator` (отдавать json + обновлять кроном). Брать ТОЛЬКО `id`, резолв иконки/названия через `listing.json` + `cdn.stalhub.dev`.
- ID которых нет в БД: вывести в отдельный блок «не найдено» (по требованию).
Метрика выгодности: `market.price / stalcoins` (уточнить: по `price`, `median` или `cheapest_lot`?).
