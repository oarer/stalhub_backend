# Пользователи

**Модуль управления аккаунтом, профилем и уведомлениями пользователя: профиль (`@me`), публичные страницы, сессии, уведомления, звёзды, баннеры, аватары и комментарии на стене профиля. Все пути монтируются под префиксом `/api/v1`.**

## Общие сведения

- Для работы с собственным аккаунтом предназначен префикс `/users/@me`, для публичных просмотров чужих страниц — `/users/id/:id` и `/users/:username`.
- Контентные эндпоинты (`@me`, онбординг, баннер, аватар) требуют валидную и не отозванную сессию `access_token` через guard `requireAuth`: он проверяет подпись JWT, наличие `sub`/`sid`, существование и неотозванность сессии, а также бан пользователя (403). Гостевые роли (`clan_guest`) ограничены разрешённым списком путей.
- Деструктивные эндпоинты (выход `DELETE /@me`, удаление аккаунта, `revoke-all`) используют `requireRefreshAuth` — он проверяет **только подпись** `refresh_token` и не перепроверяет отзыв сессии и бан-лист.
- Публичные просмотры (`/id/:id`, `/:username`) используют `requireOptionalAuth`: если валидный `access_token` передан, в `store` подставляется `user_id` (для пометки `is_starred`), иначе запрос анонимный.
- Загрузки баннера/аватара принимают только `png/jpeg/webp` (валидация MIME в схеме `t.File`).
- Общие ответы guard'ов: **401** `{ "error": "Unauthorized" }`, **401** `{ "error": "Session expired" }`, **403** `{ "error": "Account banned", "reason": …, "expire_in": … }`, **403** `{ "error": "Guest access is limited to clan features" }`.

## `GET /api/v1/users/@me`

Текущий пользователь (guard `requireAuth`). Возвращает полный payload текущей сессии.

### Тело ответа

Поля ответа (словами): `id`, `username`, `username_changed_at`, `name`, `joined_at`, `onboarded`, `social_links` (объект или `null`), `settings` (строка настроек пользователя, включая `public_profile`, либо `null`), `badges`, `roles`, `providers` (`discord`, `telegram`, `exbo` — каждый `null` или объект с данными провайдера), `customization` (объект кастомизации профиля либо дефолтный, если не задан: `layout: CLASSIC`, `banner_mode: NONE`, `banner_type: HEADER`, `banner_color: #171717`, `banner_image: null`, `card_background: NONE`, `card_color: #171717`, `avatar: null`).

### Возможные ошибки
- **401** — нет/невалидный `access_token`, сессия отозвана
- **403** — аккаунт в бане; доступ гостя ограничен

## `PATCH /api/v1/users/@me`

Обновление профиля и настроек (guard `requireAuth`). Обновление выполняется тремя писателями подряд: сначала профиль (`name`/`username`), затем `social_links`, затем настройки. Первая ошибка прерывает обработку (short-circuit) с **400**; при успехе возвращается обновлённый payload `@me` (как в `GET /@me`).

### Тело запроса

| Поле | Описание | Тип | Обязательный |
| ---- | -------- | --- | :----------: |
| `name` | Имя; непустая строка | `string` (minLength 1) | Нет |
| `username` | Юзернейм: латиница, цифры, `_` | `string` (minLength 3, maxLength 32, pattern `^[a-zA-Z0-9_]+$`) | Нет |
| `public_profile` | Открыть профиль для публичного просмотра | `boolean` | Нет |
| `layout` | Раскладка профиля | emun `CLASSIC`/`MODERN`/`COMPACT` | Нет |
| `avatar` | Источник аватара по умолчанию | enum `DISCORD`/`TELEGRAM` | Нет |
| `region` | Регион EXBO | enum `RU`/`EU`/`NA`/`SEA`/`NEA` | Нет |
| `banner_mode` | Режим баннера | enum `COLOR`/`IMAGE`/`NONE` | Нет |
| `banner_type` | Тип баннера | enum `BACKGROUND`/`HEADER` | Нет |
| `banner_color` | Цвет баннера | `string` | Нет |
| `banner_image` | Ссылка на изображение баннера | `string` | Нет |
| `card_background` | Фон карточки | enum `COLOR`/`AVATAR`/`NONE` | Нет |
| `card_color` | Цвет карточки | `string` | Нет |
| `social_links` | Соцссылки, заменяются целиком; ключи нормализуются в lowercase, пустые значения отбрасываются | `Record<string, string>` | Нет |

### Примечания
- Смена `username` ограничена кулдауном **30 дней** от `username_changed_at` (исключение — только первый выбор юзернейма через онбординг). Действует проверка уникальности (чувствительна к регистру).
- `region` для пользователя с привязанным EXBO-аккаунтом записывается напрямую в `eXBOAuth` со сбросом `region_changed_at` — это **обходит** 7-дневный кулдаун эндпоинта `/auth/exbo/region`, после чего повторно запускается определение клана.
- Пустой набор полей настроек отклоняется.

### Возможные ошибки
- **400** — любая ошибка первого сработавшего писателя:
  - `Username can be changed once every 30 days. N days remaining.` — кулдаун смены юзернейма
  - `Username is already taken` — юзернейм занят
  - `No valid fields to update`
  - `User not found`

## `DELETE /api/v1/users/@me`

Выход из аккаунта (guard `requireRefreshAuth`). Отзывает текущую сессию и очищает cookie `refresh_token` и `access_token`. Guard здесь проверяет только подпись refresh-токена.

### Тело ответа
```json
{ "success": true }
```

## `POST /api/v1/users/@me/sync-clans`

Повторно запускает определение кланов пользователя через EXBO API (guard `requireAuth`). Требует привязанный EXBO-аккаунт и заданный регион, иначе — **400**.

### Тело ответа

Поля ответа (словами): `clans` — массив профилей клана пользователя (`userClanProfile` с включённым объектом `clan`), отсортированный по `updated_at` по убыванию.

### Возможные ошибки
- **400** — `EXBO account is not linked`
- **400** — `Region is not set. Please set a region first.`
- **400** — `EXBO token is invalid`
- **400** — ошибка внешнего EXBO API (пробрасывается)

## `GET /api/v1/users/@me/settings`

Сводка настроек для экрана настроек (guard `requireAuth`).

### Тело ответа

Поля ответа (словами):
- `user_id` — id пользователя
- `public_profile` — флаг публичности профиля (по умолчанию `false`)
- `can_be_public` — `false` в текущей сборке (производная от `worksCount`, захардкожен как `0`)
- `avatar` — объект `{ current, available }`: `current` — текущий источник аватара (строчными, по умолчанию `discord`), `available` — массив строк подключённых провайдеров (`discord`/`telegram`/`exbo`)
- `avatar_image` — загруженное изображение аватара или `null`
- `region` — регион EXBO или `null`
- `region_changed_at` — время последней смены региона или `null`

### Возможные ошибки
- **404** — `{ "error": "User not found" }`

## `GET /api/v1/users/id/:id`

Публичный профиль по числовому id (guard `requireOptionalAuth`). Если целевой пользователь не включает `public_profile` — 404. Аватары; только `APPROVED` статьи; клан показывается только для публичных кланов; `data` сборок распаковывается; `is_starred` заполняется для авторизованного зрителя.

### Параметры

| Поле | Описание | Тип | Обязательный |
| ---- | -------- | --- | :----------: |
| `id` | Числовой id пользователя | `number` | Да |

### Тело ответа

Поля ответа (словами): `id`, `username`, `name`, `joined_at`, `social_links` (`null`, если нет), `stars_count` (сумма звёзд сборок и статей автора), `badges`, `builds` (массив: `id`, `title`, `tags` (массив), `created_at`, `data` (распакованный), `is_starred`), `articles` (только со статусом `APPROVED`: `id`, `type`, `title`, `image_url`, `tags`, `created_at`), `clan` (данные публичного клана или `null`), `clan_history` (до 20 записей), `customization` (без служебных полей `id`/`user_id`/`created_at`/`updated_at`).

### Возможные ошибки
- **404** — `{ "error": "User not found" }` (нет пользователя или профиль закрыт)

## `GET /api/v1/users/avatar/:id`

Аватар пользователя (публичный, без авторизации). Разрешение по приоритету: загруженный файл аватара (из `/uploads/users/avatars/`, с защитой от path traversal) → аватар провайдера (при необязательном `provider`; без него Discord побеждает Telegram; Discord-CDN отдаёт `.gif`, если id начинается с `a_`, размер 1024) → SVG-заглушка с первой буквой юзернейма. Ответы кэшируются `max-age=86400, s-maxage=86400`. Загрузки проксируются сервером.

### Параметры

| Поле | Описание | Тип | Обязательный |
| ---- | -------- | --- | :----------: |
| `id` | id пользователя | `string` | Да |
| `provider` | Провайдер аватара: `discord` или `telegram` | `string` | Нет |

### Возможные ошибки
- **404** — `{ "error": "User not found" }`
- **502** — `{ "error": "Failed to fetch avatar" }` (ошибка проксирования CDN провайдера)

| `parent_id` | id родительского комментария (на том же профиле) | `number` | Нет |

### Тело ответа

Поля ответа (словами): созданный комментарий с `author: { id, name, username }`.

### Примечания
- Побочные эффекты: владельцу профиля уходит уведомление «Новый комментарий» (если автор — не сам владелец); упоминания `@username` (regex `@([a-zA-Z0-9_]+)`) распознаются, и упомянутым пользователям (кроме автора) создаются уведомления «Упоминание».
- Если `parent_id` не найден на профиле — в теле ответа `{ "error": "Parent comment not found" }`.

### Возможные ошибки
- **401** — требуется авторизация
- **429** — превышен антиспам-лимит комментариев

## `DELETE /api/v1/users/id/:id/comments/:comment_id`

Удаление комментария (guard `requireAuth`). Доступно автору комментария или пользователю с правом `user:manage` (проверяется запросом к БД на каждый запрос).

### Параметры

| Поле | Описание | Тип | Обязательный |
| ---- | -------- | --- | :----------: |
| `id` | Числовой id пользователя | `number` | Да |
| `comment_id` | Числовой id комментария | `number` | Да |

### Тело ответа
```json
{ "success": true }
```

### Возможные ошибки
- **403** — `{ "error": "Forbidden" }` (не автор и нет права `user:manage`, либо комментарий не найден)
