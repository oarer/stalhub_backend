# Arsenal

**Модуль актуальных рыночных цен на отслеживаемый список предметов.**

## Общие сведения

- Список предметов — статичный allowlist `data/arsenal.json`; для каждого предмета с заполненным `id` берётся среднее (округлённое) по последним 20 записям истории цен аукциона региона `eu` (`/auction/:id/history?limit=20`). При сбое запроса сохраняется предыдущее значение (`currentPrice`), при его отсутствии — `0`.
- Источник цен — EXBO API через общий axios-клиент (см. контекст `sc.interceptor.ts`: серверный Bearer-токен, таймаут 10 с, один retry на 429, ошибки вида `{ status, message, details }`).
- Кэш **Redis**: ключи `arsenal:data` и `arsenal:updated_at`, TTL 6 часов. Данные считаются устаревшими, если `updated_at` старше 30 минут — тогда запускается фоновая перевалидация (stale-while-revalidate): клиенту отдаются текущие закэшированные цены, пока идёт обновление.
- Перевалидации сериализуются Redis-локом (`SET NX EX`, 5 минут, без owner-токена).
- Плановое обновление: cron `arsenal-update` в 00:00 и 12:00 по Москве; при старте и при первом отсутствии/устаревании кэша — тоже обновление.

## `GET /api/v1/arsenal`

Актуальные цены отслеживаемых предметов.

### Тело ответа

```json
{
  "updated_at": "2025-01-01T00:00:00.000Z",
  "total": 42,
  "items": [
    { "name": { "ru": "…", "en": "…" }, "id": "…", "limit": 20, "currentPrice": 12345 }
  ]
}
```

- `updated_at` — время последнего успешного обновления (ISO) либо `null`, если данных нет.
- `total` — количество предметов.
- `items[]` — элементы allowlist (поле `name` — локализованные названия, `id` — предмета, `limit` — если задан в входных данных) с добавленным `currentPrice` (`number | null`). Если кэша ещё нет, эндпоинт сначала принудительно обновит цены и вернёт свежий снимок `{ updated_at, total, items }`.

### Возможные ошибки

Нет (публичный эндпоинт).
