# Кланы

**Модуль управления кланами: жизненный цикл клана, ростер и роли, отряды, золотые дропы, отписки, аналитика боёв по скриншотам, гранатные снапшоты, настройки, привязка Discord-гильдий, приглашения гостевых аккаунтов, заметки и буст-заказы.**

Все пути в этом файле указаны под префиксом `/api/v1`.

---

## Общие сведения

### Доменная модель

- Клан — строка `clan`, ключом является **id клана из EXBO** (игровой id, например `st-...`), у каждого клана один `region`. Клан создаётся (upsert) автоматически при онбординге пользователя: его EXBO-персонажи читаются из `/{region}/characters`, и для каждой клановой принадлежности персонажа создаётся/обновляется запись клана.
- **EXBO-члены моделируются игровыми именами, а не аккаунтами**: строки `clanMember` хранят `name` (имя из игры), `rank` (игровой ранг из EXBO) и `join_time`. Связь с бэкенд-аккаунтом (`user_id`) ставится по персонажам игрового аккаунта: для привязанных к клану профилей с живым EXBO-токеном читается `/{region}/characters`, и член линкуется к `user_id` владельца персонажа, состоящего в этом клане (покрывает переименования и случаи, когда ник аккаунта отличается от имени персонажа). Несовпадение по персонажам фолбэком сверяется с `eXBOAuth.username`, `user.username` и именем гостевого аккаунта `clan_guest`; что не сопоставилось — получает `user_id: null`.
- Один бэкенд-пользователь может состоять в нескольких кланах; текущий (активный) помечается флагом `userClanProfile.is_active`. Смена клана на другой не удаляет остальные профили — только деактивирует их.
- **Lifecycle `FROZEN → ACTIVE`.** Клан всегда создаётся как `FROZEN`. Лидер может вызвать `POST /clan/register` — клан становится `ACTIVE`; `POST /clan/freeze` возвращает его в `FROZEN`. Только `ACTIVE`-кланы участвуют в часовом кроне синхронизации, автоматическом расписании золотых дропов и гранатных снапшотах. Пока клан `FROZEN`, офицерские управляющие маршруты (почти все настройки, золото и т.п.) недоступны — `requireClanOfficer` требует статус `ACTIVE`.
- **Иерархия** (сверху вниз, см. `guards.ts`):
  - **Member** — любой пользователь, у которого есть профиль с `is_active: true` (в рангах EXBO это любые игровые ранги — `RECRUIT`, `SERGEANT` и т.п.); этот guard записывает `store.clan_id`.
  - **Officer** — member + клан `ACTIVE` + игровой ранг из множества `{OFFICER, COLONEL, LEADER}`.
  - **Leader** — member, причём выполняется хотя бы одно из: (1) у `clanMember` ранг `LEADER`; (2) имя лидера в записи клана (`clan.leader`) совпадает с EXBO-username пользователя (без учёта регистра); (3) **live-проверка через EXBO API**: у одного из персонажей пользователя `clan.info.id === clan_id` и `clan.member.rank === 'LEADER'` (дешифруется EXBO-токен пользователя; при ошибке API/токена проверка завершается отказом — fail closed). Роль `clan_guest` — это только backend-роль ограниченного гостевого аккаунта: гости по-прежнему проходят member/officer/leader-проверки на любых маршрутах.

### Авторизация и «clanContext»

- Все маршруты модуля (`/clan/...`) сидят на общем Elysia-instance `clanContext` (scope). В store пер-запроса резолвятся:
  - `authUserId` — числовой id пользователя из JWT, выставляется guard'ом `requireAuth` (cookie `access_token`; проверяются `sub`/`sid`, неповторявшаяся (`!revoked`) сессия и отсутствие бана). Для роли `clan_guest` доступ ограничен жёсткими префиксами (`/api/v1/clan/`, `/api/v1/users/@me`, `/api/v1/health`).
  - `clan_id` — id активного клана вызывающего, выставляется `requireClanMember` (и построенными на нём guard'ами), далее переиспользуется хендлерами без повторных запросов.
- Guards (цепочки `beforeHandle`):
  - `requireAuth` — 401 `Unauthorized` / `Session expired`; 403 `Account banned` / `Guest access is limited to clan features`.
  - `requireClanMember` — 401 `Unauthorized`; 403 `You are not in a clan`.
  - `requireClanOfficer` — дополнительно 403 `Clan is not active. Register it first.` и 403 `Officer rank required`.
  - `requireClanLeader` — 403 `Leader rank required`.

### Что где живёт

- **Публичные группы:** `GET /clans` и `GET /clans/:clan_id` (порт `routes/public.ts`, смонтированы отдельно на `/clans`) работают **без авторизации** и отдают только кланы `is_public`.
- **Золото (дропы):** `routes/gold.ts` + `services/gold.ts`. Дропы создаются на каждый `ACTIVE`-клан на фиксированные часы МСК **[10, 13, 16, 19, 22]** ежедневно (в БД хранятся как UTC = час − 3). Фоновый крон в 21:05 МСК дособирает расписание на следующие два дня; дропы старше 30 дней удаляются. Офицер отмечает участников и меняет статус дропа.
- **Гранатные снапшоты:** `services/grenades.ts`. По крону на каждой игровой контрольной точке + **5 минут** кулдауна (`BEFORE_STAGES`, `BETWEEN_1_2`, `BETWEEN_2_3`, `BETWEEN_3_4`, `AFTER_STAGES`) снимается снапшот суммарного стата `gre-thr` («гранат брошено» из профиля персонажа EXBO). «Этап» — дельта между двумя соседними чекпоинтами; член учитывается на этапе только если его значение есть **в обоих** чекпоинтах. Запросы к EXBO размазываются по ротирующемуся пулу токенов членов (round-robin по клану), истёкшие access-токены обновляются через `https://exbo.net/oauth/token`; результаты кэшируются в Redis на 6 часов (при снапшоте кэш обходится). Снапшоты пропускаются: у кланов с `sunday_activity: NONE` — всегда; в воскресенье — для типов событий, не совпадающих с `sunday_activity`. Пустой пул токенов — снапшот для клана не сохраняется. Гранатные боксы — постоянный инвентарь (дата-«sentinel» `'permanent'`), суммарно по ключу (name, type).
- **Рейтинг кланов:** `services/rating.ts`. Тир по рейтингу: `S ≥ 2201`, `A ≥ 2000`, `B ≥ 1750`, `C ≥ 1500`, `D ≥ 1250`, иначе `E`. Рейтинг меняется **только для турнирных сессий** (`TOURNAMENT`), чьё `started_at` попадает в `clanSeason`: +50 победа / −50 поражение, нижний порог 0. Применение/откат (`applySessionRating`, `reverseSessionRating`) выполняются в транзакциях, которые берут строки сессии и клана в **`FOR UPDATE`** (защита от гонок под параллельной нагрузкой). Каждое изменение записывается в `clanRatingEvent`, поэтому при исправлении или удалении сессии дельта откатывается перед записью новой (рейтинг никогда не «компаундируется»).
- **Эндпоинты Discord-бота:** внутри `/clan` есть группа `/clan/bot/*` (JWT-авторизация) для выпуска токенов привязки и управления гильдиями. **Сервисный API**, которым пользуется сам Discord-бот, находится вне `/clan` — `/api/v1/internal/bot/*`; все его маршруты защищены заголовком **`x-bot-secret`** (равен `env.DISCORD_BOT_SERVICE_JWT`), иначе 401 `Invalid bot secret`. Этот API покрывает поиск кланов/гильдий, отписки по `discord_id`, приём скриншотов с автоопределением этапа (`detectStageSlot`), запрос текущего/следующего слота стадии (`/stage`), создание/погашение гостевых инвайтов и привязку гильдии по одноразовому токену (`/link`).
- **Расписание игровых стадий** (`src/lib/stages.ts`, полуинтервалы `[start, end)`, время МСК):
  | Тип | Дни недели (JS: 0 = вс) | Этапы |
  | --- | --- | --- |
  | `TOURNAMENT` | 4 (чт), 5 (пт), 6 (сб) | 1: 20:00–20:25; 2: 20:25–20:50; 3: 20:50–21:15 |
  | `BRAWL` | 0 (вс), 1 (пн), 2 (вт), 3 (ср) | то же (3 этапа 20:00–21:15) |
  | `BASE_CAPTURE` | 0 (вс) | 4 этапа по 25 мин: 19:00–20:40 |

  Четверг присутствует в расписании и `TOURNAMENT`, и `BRAWL`; приоритет у `TOURNAMENT` (`DETECT_ORDER`). `nextStageSlot` сканирует ближайшие 7 дней и никогда не отдаёт этап дальше недели.
- **Время:** всё время событий — Московское, реализовано фиксированным смещением **UTC+3** без DST (`src/lib/msk.ts`). Объекты `Date` из `mskNow()` физически сдвинуты на +3h и пригодны только для вывода МСК-календарных частей.
- **Регионы (enum `Regions`):** `RU`, `EU`, `NA`, `SEA`, `NEA`.
- Ошибки бизнес-валидации в сервисах выглядят одинаково: ответ `{ "error": "<причина>" }` (для явных `set.status` см. статусы у конкретных маршрутов; необработанные throw в сервисах приводят к стандартному ответу Elysia).

## Публичный каталог кланов (без авторизации)

Публичный листинг смонтирован отдельно (`routes/public.ts`) на `/clans` — **без** `clanContext` и без JWT. Отдаются только кланы с `is_public: true`; для неизвестного или закрытого клана — 404.

### `GET /clans`

Список публичных кланов.

### Параметры

Нет.

### Тело ответа

Массив «публичных карточек» кланов (см. `publicClanPayload`):

| Поле | Описание | Тип |
| --- | --- | --- |
| `id` | EXBO id клана | `string` |
| `name` | Название | `string` |
| `tag` | Тег | `string` |
| `alliance` | Альянс/фракция | `string` |
| `description` | Описание | `string` |
| `leader` | Игровое имя лидера | `string` |
| `member_count` | Число членов | `number` |
| `status` | `FROZEN` / `ACTIVE` | `string` |
| `is_public` | Клан публичен | `boolean` |
| `recruiting` | Идёт рекрутинг | `boolean` |
| `leader_discord`, `clan_discord` | Discord-контакты; возвращаются **только пока `recruiting: true`** | `string \| null` |
| `paid_recruitment` | Платный рекрутинг | `boolean` |
| `rating` | Рейтинг | `number` |
| `tier` | Тир `E`–`S` | `string` |
| `guilds_per_week` | Лимит гильдий в неделю (или null) | `number \| null` |
| `schedule` | Нормализованное расписание: `brawls_per_week`, `brawls_mandatory`, `sunday_activity` | `object` |
| `boost_mode`, `grenade_mode` | `ISSUED` / `SELF` | `string` |
| `created_at` | Дата создания | `string` (ISO) |

Сортировка: по `created_at` убыванию.

### Возможные ошибки

Нет специфичных.

## Профиль и жизненный цикл клана

Маршруты `routes/me.ts`. Чтение своих кланов/профиля — любому аутентифицированному; регистрация и заморозка — лидеру; синхронизация и редактирование членов — офицерам.

### `GET /clan/me`

Профиль активного клана текущего пользователя. Если ни один из профилей не отмечен активным, сервис молча продвигает один из существующих профилей пользователя в активные; если профилей нет совсем — ответ `null`.

### Параметры

Нет.

### Тело ответа

Объект `userClanProfile` с вложенным кланом:

| Поле | Описание | Тип |
| --- | --- | --- |
| `user_id` | id аккаунта | `number` |
| `clan_id` | EXBO id клана | `string` |
| `region` | Регион профиля | `string` |
| `is_active` | Профиль активен | `boolean` |
| `updated_at` | Дата обновления | `string` (ISO) |
| `clan` | Строка клана (поля `clan`) | `object` |

### Возможные ошибки

- **401** — не аутентифицирован (guard `requireAuth`).

---

### `GET /clan/my-clans`

Все кланы, к которым привязан пользователь (профили + вложенные кланы), отсортированы по `updated_at` убыванию.

### Параметры

Нет.

### Тело ответа

Массив объектов вида `GET /clan/me` (без «продвижения» активного).

### Возможные ошибки

- **401** — не аутентифицирован.

### `POST /clan/switch`

Атомарное переключение активного клана пользователя (транзакция: деактивируются все остальные профили, активируется целевой).

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `clan_id` | EXBO id клана, в который переключаемся | `string` | Да |

### Тело ответа

Пустой ответ при успехе (Elysia-модель `void`). Бизнес-ошибка (нет профиля у пользователя на этот клан) — исключение сервиса `You are not a member of this clan`.

### Возможные ошибки

- **401** — не аутентифицирован.

---

### `POST /clan/register`

Переводит активный клан пользователя в статус `ACTIVE` (регистрация клана в системе).

### Параметры

Нет (guard: `requireClanLeader`).

### Тело ответа

Строка клана `clan` (все поля). Перед активацией выполняется `sync`; сбой синхронизации логируется и не блокирует регистрацию. Если у пользователя нет ни одного клана — исключение `No clan linked to user`.

### Возможные ошибки

- **401** — не аутентифицирован.
- **403** — не лидер клана (`Leader rank required`).

---

### `POST /clan/sync`

Полная пересинхронизация клана из EXBO API (guard: `requireClanOfficer`).

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `region` | Регион синхронизации; по умолчанию регион клана, иначе `RU` | `RU \| EU \| NA \| SEA \| NEA` | Нет |

### Тело ответа

```json
{
  "clan_id": "st-...",
  "member_count": 7,
  "members_synced": true
}
```

Семантика: (1) обновляется информация клана; (2) ростер членов берётся первым живым дата-токеном среди привязанных пользователей — без токена список членов считается пустым, и все строки `clanMember` клана перезаписываются в `[]` (delete-and-recreate); (3) члены линкуются к аккаунтам по имени без учёта регистра (`eXBOAuth.username` → `user.username` → имя `clan_guest`), несостыкованные получают `user_id: null`; (4) при смене `region` клана он прокидывается во все профили.

### Возможные ошибки

- **401** — не аутентифицирован.
- **403** — клан не `ACTIVE` или недостаточный ранг (`Clan is not active. Register it first.` / `Officer rank required`).

## Отряды (squads)

Маршруты `routes/squads.ts`, бизнес-логика `services/squad.ts`. Отряд — из 5 слотов (`slot` 0–4) на карту. Инварианты: максимум 6 отрядов на одну карту, уникальное имя отряда в пределах (клана, карты), один слот на члена, член может занимать **ровно один слот во всех отрядах одной карты** (назначение вытесняет прошлые места), лидер — строка-член конкретного отряда.

Модель `gear_override` (слот): `{ weapon_primary?, weapon_secondary?, weapon_pistol?, armor?, bio_armor? }` (nullable строки) + `{ build_fat?, build_speed? }` (nullable числа); `null` в теле очищает пресет.

Ответы отрядов включают `members[]`, `leader` и `requests[]` (заявки) — каждый элемент с вложенным `member` (запись `clanMember` + `user`).

### `GET /clan/squads/:clan_id`

Список отрядов клана (любой аутентифицированный пользователь). Сортировка: карта, затем дата создания.

### Параметры

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `clan_id` | EXBO id клана | `string` | Да |

### Тело ответа

Массив отрядов (поля строки `clanSquad` + `members`, `leader`, `requests`).

### Возможные ошибки

- **401** — не аутентифицирован.

## Аналитика боёв (sessions / скриншоты)

Маршруты `routes/analytics.ts` (группа `/clan/analytics`), логика `services/analytics.ts` + `services/ai.ts`.

Пайплайн: офицер создаёт сессию (клановую или личную; тип по умолчанию `TOURNAMENT`) и загружает **не более одного скриншота на сессию** (multipart, только `image/png`, `image/jpeg`, `image/webp`). Файл пишется в `uploads/screenshots`, запускается фоновый AI-разбор (OpenAI vision, до 3 попыток с backoff, на время разбора `ai_status = processing`). По результату: (a) для каждого члена роcтера проставляется посещаемость `PRESENT`/`ABSENT`, источник `ai`, существующие `manual`-строки не перетираются; (b) `map_name` обновляется из AI-ответа (суффикс после `#` срезается); (c) когда **все** скриншоты сессии `done`, агрегируется `ai_summary` и применяется рейтинг клана (`applySessionRating`). Ошибки разбора помечают `ai_status = error` (ретраится `retry`).

Модификации — только офицерские; чтение статистики — любому аутентифицированному; месячная посещаемость — члену клана.

### `POST /clan/analytics/sessions`

Создать сессию боя (guard: `requireClanOfficer`). Клан берётся из `store.clan_id` (активный клан офицера).

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |

| `map_name` | Название карты | `string` | Да |
| `type` | Тип события; по умолчанию `TOURNAMENT` | `TOURNAMENT \| BRAWL \| BASE_CAPTURE` | Нет |
| `started_at` | Время начала (ISO) | `string` | Нет |
| `stage_number` | Номер этапа (или `null`) | `number` (≥ 1) \| `null` | Нет |

### Тело ответа

Созданная сессия `stageSession`: `id`, `external_id`, `region`, `map_name`, `type`, `started_at`, `ended_at`, `stage_number`, `creator_id`, `clan_id`, `ai_summary`, `created_at`, `updated_at`.

## Приглашения и гостевые аккаунты

Маршруты `routes/invites.ts`, логика `services/invites.ts`. Все эндпоинты — **только для лидера**. Гостевой аккаунт (`clan_guest`) заводится под EXBO-члена без своего аккаунта, привязывается к роcтеру по имени (без регистра). Код — 8 символов (тот же алфавит без путаницы), срока действия нет; инвалидируется только погашением, отзывом или киком. **Плейнtext-креденшелы возвращаются ровно один раз.**

### `GET /clan/invites`

Список инвайтов клана (по дате создания убыванию).

### Параметры

Нет.

### Тело ответа

Массив `clanInvite`:

| Поле | Описание | Тип |
| --- | --- | --- |
| `id` | id инвайта | `number` |
| `code` | Код | `string` |
| `clan_id` | клан | `string` |
| `user_id` | гость | `number` |
| `claimed_by` | кто погасил | `string \| null` |
| `claimed_at` | когда погашен | `string \| null` |
| `created_by` | кем создан (`user:<id>` / `discord:<id>`) | `string` |
| `created_at` | дата создания | `string` (ISO) |
| `user` | `{ id, username, name }` | `object` |

### Возможные ошибки

- **401** / **403** — guards (`Leader rank required`).

---

### `POST /clan/invites`

Создать гостевой аккаунт для члена клана. Имя должно совпадать с членом роcтера (без регистра). Создаются: пользователь с ролью `clan_guest`, код, активный `userClanProfile`, линк `clanMember.user_id`. Генерируется юзернейм `guest_<имя>_<4 символа>` и пароль (12 символов, base64url). При коллизии кода — до 5 ретраев.

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `nickname` | Игровое имя члена клана | `string` (не пустое) | Да |

### Тело ответа

```json
{
  "code": "ABC23478",
  "username": "guest_Player_abcd",
  "password": "qxyz...",
  "clan_id": "st-...",
  "user_id": 42,
  "nickname": "Player"
}
```

### Возможные ошибки

- **401** / **403** — guards.
- `Nickname is required`, `Clan not found`, `"<имя>" is not in the clan member list`.

---

### `POST /clan/invites/bulk`

Массовое создание гостей (до 100 имён за раз). Отдельные неудачи не прерывают остальные; по каждому имени возвращается результат.

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `nicknames` | Список игровых имён | `string[]` (1–100, каждое ≥ 1 символа) | Да |

### Тело ответа

Массив записей: `{ "ok": true, "code": "...", "username": "...", "password": "...", "clan_id": "...", "user_id": 42, "nickname": "Player" }` либо `{ "ok": false, "nickname": "Player", "error": "<причина>" }`.

### Возможные ошибки

- **401** / **403** — guards.
- Ошибки валидации схемы (пустой массив, > 100 элементов) — 422.

---

### `DELETE /clan/invites/:id`

Отозвать инвайт: транзакционно удаляются строка инвайта и сам гостевой пользователь.

### Параметры

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `id` | id инвайта | `number` | Да |

### Тело ответа

```json
{ "ok": true }
```

### Возможные ошибки

- **401** / **403** — guards.
- `Invite not found`.

---

### `DELETE /clan/invites/guest/:user_id`

Кикнуть гостя из клана с удалением аккаунта: удаляются профиль, разрывается линк `clanMember.user_id` (→ null), удаляются инвайты и пользователь (одна транзакция).

### Параметры

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `user_id` | id гостевого аккаунта | `number` | Да |

### Тело ответа

```json
{ "ok": true }
```

### Возможные ошибки

- **401** / **403** — guards.

## Заметки по членам клана

Маршруты `routes/notes.ts` (группа `/clan/notes`), логика `services/notes.ts`. **Только офицеры.** Ровно одна заметка на члена (`unique member_id`): upsert заменяет существующую и меняет автора; контент обрезается до 512 символов.

### `GET /clan/notes`

Все заметки клана (по дате создания убыванию).

### Параметры

Нет.

### Тело ответа

Массив `clanMemberNote`:

| Поле | Описание | Тип |
| --- | --- | --- |
| `id`, `clan_id`, `member_id`, `author_id` | базовые поля | `number / string` |
| `content` | Текст заметки (≤ 512) | `string` |
| `created_at`, `updated_at` | метки | `string` (ISO) |
| `author` | `{ id, username, name }` | `object` |
| `member` | `{ id, name }` | `object` |

### Возможные ошибки

- **401** / **403** — guards.

---

### `POST /clan/notes`

Создать/перезаписать заметку члена (офицер). Меняет `author_id` на отправителя.

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `member_id` | id члена клана | `number` | Да |
| `content` | Текст (≤ 512) | `string` | Да |

### Тело ответа

Созданная/обновлённая заметка (с `author`).

### Возможные ошибки

- **401** / **403** — guards.
- `Участник не найден в клане`.

---

### `PATCH /clan/notes/:note_id`

Отредактировать заметку по id (офицер).

### Параметры

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `note_id` | id заметки | `number` | Да |

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `content` | Новый текст (≤ 512) | `string` | Да |

### Тело ответа

Обновлённая заметка (с `author`). Автор не меняется.

### Возможные ошибки

- **401** / **403** — guards.
- `Заметка не найдена`.

---

### `DELETE /clan/notes/:note_id`

Удалить заметку (офицер).

### Параметры

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `note_id` | id заметки | `number` | Да |

### Тело ответа

```json
{ "ok": true }
```

### Возможные ошибки

- **401** / **403** — guards.
- `Заметка не найдена`.

## Буст-заказы

Маршруты `routes/boosts.ts` (группа `/clan/boosts`), логика `services/boost-order.ts`. Заказы агрегируются по `(player, item)` со счётчиком `count`; все строки несут дату-`sentinel` `'permanent'`. Добавление заказов запрещено в режиме `SELF` (`/clan/boost-mode`); удаление — офицерское, по индексу в порядке создания.

### `GET /clan/boosts`

Список заказов клана (guard: `requireClanMember`).

### Параметры

Нет.

### Тело ответа

```json
{
  "orders": [
    { "id": 1, "clan_id": "st-...", "date": "permanent", "player_id": 5, "item_id": "item-id", "item_name": "Буст опыта", "count": 3, "created_at": "...", "player": { "id": 5, "name": "Player" } }
  ]
}
```

### Возможные ошибки

- **401** / **403** — guards.

---

### `POST /clan/boosts`

Добавить буст-заказ (guard: `requireClanMember`). Для существующей пары `(player, item)` `count` инкрементируется; `item_name` обрезается до 200 символов.

### Параметры

#### Тело запроса

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `player_id` | id члена клана | `number` | Да |
| `item_id` | id предмета | `string` | Да |
| `item_name` | Название предмета | `string` | Да |
| `count` | Количество | `number` (≥ 1) | Да |

### Тело ответа

Актуальный список заказов (`{ orders: [...] }`).

### Возможные ошибки

- **401** / **403** — guards.
- В режиме `SELF` — исключение сервиса `Self-boost mode`; `Clan not found`, `Member not found in clan`.

---

### `DELETE /clan/boosts/:index`

Удалить заказ по индексу создания (guard: `requireClanOfficer`). Несуществующий индекс — no-op.

### Параметры

| Поле | Описание | Тип | Обязательный |
| --- | --- | --- | :---: |
| `index` | Индекс в упорядоченном по созданию списке | `number` | Да |

### Тело ответа

Актуальный список заказов (`{ orders: [...] }`).

### Возможные ошибки

- **401** / **403** — guards.
